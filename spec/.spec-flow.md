# Workspace notes

**Per-feature `spec.md` is canonical.** Each feature lives in its own folder under
`spec/features/<slug>/` with a `feature.md` manifest plus its `spec.md`, `plan.md`, and
`tasks.md`. Those files are the source of truth — edit them directly.

**These files are generated — never hand-edit them:**

| File | Generated by |
| --- | --- |
| `spec/product.md` | `node scripts/assemble.mjs` |
| `spec/dashboard.md` | `node scripts/dashboard.mjs` |
| `spec/view.html` | `node scripts/view.mjs` |
| `spec/analyze-product.md`, `spec/features/*/analyze.md` | the `analyze` skill |

They are listed in `spec/.gitignore`. `scripts/status.mjs` prints a plain-language read of where
a feature (or the whole project) stands; `scripts/validate.mjs` lints the workspace.

**`constitution.md` and `product-global.md` are main-branch-only.** Change them through their own
pull request, never inside a feature branch — editing either restages every feature's pre-build
check.

**Start a new feature** with `/spec-flow:feature`, or run `/spec-flow:flow` to be walked through
the next step automatically.

**Design stage is off** for this workspace (`requires_design: false`), so every feature's design
artifact reads `n/a` and planning does not wait on one. A feature that does warrant a design pass
can turn it back on by setting `requires_design: true` in its own `feature.md`.
